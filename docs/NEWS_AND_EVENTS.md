# Как писать новости и готовить события

## Новости внутри игры — уже подключено

1. Остановить Play. В Explorer открыть ReplicatedStorage → ModuleScript NewsConfig.
2. Добавить новую запись первой в списке: уникальный Id, отображаемая Date, Title и Body. Body — обычный текст между [[ и ]]. Не использовать закрывающие ]] внутри статьи.
3. Сохранить и проверить F5 → Почта → Новости. Старые статьи можно оставить ниже.
4. Для живой игры выполнить File → Publish to Roblox. Save to Roblox сохраняет версию, но не публикует её игрокам.

Пример записи:

```lua
{Id = "update-2026-11-20", Date = "20 ноября 2026", Title = "Новые темы офиса", Body = [[
Добавили новые варианты оформления кабинета.
Исправили отображение дохода на компактной панели.
]]},
```

Этот способ доставляет статьи в новые серверы опубликованной версии. Уже работающие серверы сохраняют загруженный код. Чтение статей пока не сохраняется между входами; персональных подарков в NewsConfig нет.

Для новостей всем уже играющим без перепубликации рекомендован следующий отдельный шаг: серверный обработчик Live Content на ConfigService и редактор статей. Сейчас такого обработчика нет. Roblox поддерживает JSON-конфигурации и обновление значений без рестарта, но их требуется явно подключить к коду: [Experience configs](https://create.roblox.com/docs/production/configs).

## Анонсы и события Roblox

В Creator Dashboard открыть experience → Engagement → Events & Updates. Там создаются публичные анонсы и запланированные события с названием, изображением, описанием и временем. Игроки могут подписаться на уведомление о начале. Уведомления обновлений получают включившие их игроки; это отдельный механизм от игровой почты. Подробности: [Experience events and updates](https://create.roblox.com/docs/production/promotion/experience-events).

Анонс не создаёт игровой контент сам. Для игрового события нужно отдельно реализовать правила, ограничения и награды.

## Предлагаемый порядок игрового ивента

1. Определить тему, цель игрока, точное начало/окончание по Москве и состав наград.
2. Подготовить оформление и правила; лучше начинать с коллекционных рамок/тем, без постоянного множителя денежного дохода.
3. Проверить на тестовом experience до объявления: начало, окончание, повторный вход, отсутствие двойной награды, поведение старых предметов.
4. Подключить расписание и выключатель события на сервере, например через ConfigService; предусмотреть откат/остановку. События и награды в текущем коде ещё не реализованы.
5. Опубликовать игровые изменения, затем новость в почте и анонс в Events & Updates.

Для усилений удачи учитывать утверждённый общий потолок. Нельзя просто удвоить все выплаты/шансы поверх остальных бустов без пересчёта экономики. Сезонные рамки по v0.2 косметические, уже выданные не исчезают после конца события.
