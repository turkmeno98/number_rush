## Шаг 34 — общий региональный розыгрыш

Реальный Play: новая выдача сохранила EconomyVersion=3, регион, цену 5000 и код из допустимого пула, выпал обычный номер. Меню видно в компактном виде, Sidebar.boosts отсутствует, нижняя кнопка есть; меню и компактная панель не перекрываются. Настройки открываются поверх мира, статья из NewsConfig читается. Паспорт удалён из активного UI. Многосерверные отказы и полное истощение пулов не тестировались.

## Шаг 33 — рабочий стол, компактный терминал, EquipBest

15 проверок точного модуля слотов на искусственных сессиях в Studio с подменённым хранилищем: сортировки/равенства, замена, сохранение лучших в прежних слотах, отсутствие повторной записи, ревизия, исключение предметов других активностей, пустая/неполная коллекция, замена без ожидания, последний источник, отказ записи, вызов доходного hook и занятая сессия. Все пройдены. Исторические тесты tests/income_slots.lua обновлены под отмену cooldown; их Lua 5.4 runner в текущей Windows-среде не запускался.

Реальный Play: кнопка оптимизации сохранила три слота, новый запуск восстановил назначения. Из компактного терминала проведена одна выдача с разворачиванием в процессе: анимация и результат одинаковы, номер и NextSpinSequence увеличились на один. Через mouse MCP проверены меню «Пуск», профиль, отдельные бусты, вкладка наград (без фиктивной выдачи), ползунок громкости (SoundGroup и подпись изменились примерно до 50%). Настоящего аудиотрека для проверки звучания пока нет. Многопользовательский просмотр чужого профиля ещё не проверялся отдельным вторым клиентом.

## Следующие ручные проверки

1. Установить IncomeSlotService и обновлённый GameServer: проверить загрузку баланса и три папки IncomeSlots. Затем подключить UI назначения и проверить реальную установку/перезапуск.

3. Повтор того же sequence не списывает деньги второй раз; старый sequence после следующей выдачи не запускает новый платёж.
4. Двойное нажатие, смена оператора во время анимации, недостаток денег, 25/25 мест.
5. Два сервера одновременно резервируют один полный номер: только один владелец.
6. Аварийное завершение после каждого этапа журнала: следующий вход восстанавливает согласованное состояние.
7. Неизвестный результат записи не вызывает автоматический второй номер/возврат.
8. Задержка API дольше 60 секунд: UI не делает новый запрос самостоятельно.

Для отказных тестов использовать отдельные тестовые профили и номера. Не менять общие имена хранилищ и не включать BalanceSaveTest без понимания, какой баланс он перезаписывает.
